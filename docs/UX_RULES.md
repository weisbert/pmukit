# 交互规则（GUI 壳和后端共同遵守）

依据：ISO 9241-210 以用户为中心的流程、Nielsen 十条启发式、Shneiderman 对象-动作模型、EDA 工具的既有形态（Setup → Job monitor → Results → Log，CIW 命令回显）。

## 对象和动词

先列对象，再给动词。按钮放常用的两三个，右键菜单放全部。对象清单：项目、引脚、corner / 温度 chip、轨、计划组、run、评分格、模型块、曲线、交付文件、摘要块。每个对象的动词表在 `design/gen_screens.py` 的菜单定义里，实现时从同一处生成按钮和菜单。

## 命令回显

每个屏底部有一条 `$ pmukit …`，随当前状态变化，等价于用户刚才在界面上做的事。GUI 能做的，CLI 都能做；反之不要求。这是脚本化和夜里批跑的入口，也是"我到底做了什么"的答案。

## 错误消息四段式

每条错误固定四段，缺一不可：

- **What**：发生了什么，一句。
- **Why**：为什么，一句，说机制不说猜测。
- **Do**：现在怎么办，给一到两个可点的动作。
- **Where**：文件、行号、日志的链接。

错误出现时，出错对象所在的表不消失，修复动作就在旁边。

## 状态

每个屏四种状态都要有稿：空、加载、错误、部分。加载超过 2 秒必须说明在做什么，用骨架行不用独立转圈。部分结果允许交付，但保留意见印进报告和 `.va` 头。

## 撤销

配置类改动（三问、计划勾选、评分覆盖）可撤销，Ctrl Z。已提交的 run 不撤销，用"跳过"或"杀掉"。

## 帮助

右上角 `? Help`：本屏三句话、本屏快捷键、全局快捷键。字段级 `?` 只用在三问这类需要解释的地方。`pmukit help <screen>` 打印同一段文字。

## 快捷键

全局：`?` 帮助、`Ctrl K` 命令面板、`0…5` 切屏、`Ctrl Enter` 主按钮、`Ctrl Z` 撤销、`Esc` 关闭。各屏的在帮助面板里。

## 状态可见

Run 屏之外，任何后台动作（解析网表、拟合、写交付）都在当前屏顶部显示进度条和正在做的事，完成后留一条到 Home 的最近活动。

## 评估

阶段 1 结束做一次出声思考测试（`USABILITY_TEST.md`），改完再测一轮。上线前对照 Nielsen 十条做一次启发式走查，每条给出证据或缺口。
