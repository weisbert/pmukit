# pmukit 重构计划（2026-09-15 头脑风暴稿）

> 这是计划，不是开工单。开建放在一个新的 ultracode 会话，拿到明确的 go 之后。
> 老仓 `LDO_modeling` 已转 private，只当参考库用；本仓公开、只放工具。

## 1. 为什么重做

老仓是 316 个 commit 的研究日志，方法已经验证，但用起来有五个痛点：

| # | 痛点 | 病根 |
|---|------|------|
| 1 | 只覆盖 TT 角，IPTAT 没有温度 | 模型对工艺零依赖；"重发射 ≠ 重表征"，多角需要多次表征，而编排多角跑批没做 |
| 2 | 交互难受 | 8000 行单文件 PyQt5 向导，表单驱动；用户要看的是"跑了什么、为什么、结果喂给谁" |
| 3 | 不知道哪些仿真真需要 | 覆盖档位一把梭，没有"参数 X 需要观测量 Y 在哪些角"的映射 |
| 4 | 跑了什么模糊 | 数据契约是 npz 字符串键（`tr_pll_2m_tt_25c`、L0-L5 标签），没有运行台账 |
| 5 | HB/PSS 不收敛 | 发射器不变量散落在代码、手改 `.va` 和几十个测试里；非线性项默认开 |

另外还有：两套仿真器工具链每个功能写两遍；两套模型家族并存；交付件手改不可复现；验收环在仓库外；客户数据曾进过公开仓。

## 2. 硬约束（已定，不再讨论）

- **公开仓，客户数据不进 git。** 真数据、真 manifest、交付 `.va` 放 `$PMUKIT_DATA`，桌面和盒子各一份。提交前有闸（本地 `.pmukit-denylist`）。测试只用合成件。
- **PVT 轴按项目配置。** 工艺角、温度、VSET 档、每路电源范围全部从项目配置读，代码里不写死任何一个数。换项目只换配置。
- **温度在每个工艺角内连续。** 用户可以设任意温度；稳定性最差点可能在中间温度，每个角要扫一遍找。
- **大信号要，但"要么对，要么关"。** 每个非线性项单独开关，单独过 HB 首步残差体检；RF/HB 交付档默认只开经过体检的项。
- **界面走 web。** 盒子上 webprobe 四项全绿。单个内联 HTML，标准库服务器，无 CDN，无 Qt。
- **仿真器只留 Spectre/ALPS。** 合成 LDO 回归改在本地 Spectre 18.1 跑，ngspice 退役，发射器只写 Verilog-A 一份。

## 4. 新架构：六个环节，四份契约

```
项目配置 ──> [规格] ──> [计划编译] ──> [运行] ──> [拟合] ──> [发射] ──> [验证] ──> 交付
              模型规格     最小测量计划    台账      类型化数据集   .va 库    分数+体检   模型库+溯源
```

四份契约先写，代码围绕契约长：

1. **模型规格**：每个端口有哪些块；每个参数需要哪个观测量、在哪些角/温度/VSET/负载；属于 HB 档还是大信号档。
2. **数据集**：有维度的类型化数据（端口 × 角 × 温度 × VSET × 负载 × 分析），不再是字符串键。
3. **运行台账**：每次仿真一条记录：角、分析、激励、网表哈希、PSF 路径、状态、耗时、被哪个参数消费。
4. **交付物**：按 PDK 同一个 corner 变量索引的模型库 + 溯源头（配置哈希、数据哈希、日期）+ 有效包络 + 报告。

环节要点：

- **计划编译**：从模型规格反推最小测量集，按 AC 叠加去重、按网表分组，给出成本估计和每条 run 的"为什么存在"。这是痛点 3 和 4 的解。
- **运行**：Donau/ALPS/ADE 三个后端一个接口，缓存、resume、写台账。基本是复用。
- **发射**：单一发射器，只用白名单原语；数值条件 lint（每个元件在 nharms×f0 处的动态范围）；温度契约统一；每角一个 section。
- **验证**：每角分块分数 + 盒子上的 HB 首步残差体检门（逐项开关，任一项比全关高 10 倍即不通过）+ 包络报告 + 合成件回归。
- **web 界面**：四个屏。Plan：将跑什么、为什么、多少钱。Run：台账和实时状态。Model：烘进去了什么、包络、每角评分。Deliver：文件和溯源。先用 Claude Design 出稿再写。

## 6. 还没讨论完的（下次先聊这些）

- **到底建什么。** 按用户分：VCO 相噪/HB、KVCO/频率、杂散、大信号瞬态。每类要的量不同，见下表草稿，需要逐行确认。
- **大信号事件清单。** 芯片里真实发生的是哪些：模式切换负载跳变、上电启动、VSET 切换？设计师最后读的是跌落 mV、恢复时间、还是过冲上限？这决定表征跑什么。
- **电流偏置端口。** VCO 是电流偏置的，现有 sink 模型差 3 到 5 dB、PTAT 单温、电流噪声为零。可能比 Zout 更要紧，要不要升为一等块？
- **合成件回归的范围。** 14 个玩具 LDO 全留，还是挑代表？

建模内容草稿：

| 用户 | 必须有 | 可选 |
|---|---|---|
| VCO 相噪 / HB | 轨电压噪声、偏置电流噪声、载波附近 Zout/PSRR、各角 DC 和偏置电流、启动卸载不破坏 HB 初值 | |
| KVCO / 频率 | DC 电压、偏置电流随工艺/温度/VSET | 低频 Zout |
| 杂散 | Zout、PSRR 在载波 ± 干扰处 | 内生 spur |
| 大信号瞬态 | 负载阶跃跌落/过冲、恢复时间、限流/dropout、不能吸电流 | 启动、VSET 切换 |
